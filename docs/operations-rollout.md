# Общий рабочий контур

## Что меняется

Заказ создаёт администратор (фото / JSON), проверяет строки и назначает активному
комплектовщику. Сборщик видит только назначенные ему заказы. Распознавание на API
тоже закрыто для сборщиков. WMS1 пока не подключена: `shared/order-model.js` —
независимый числовой контракт будущего адаптера, а не заявление о поддержке API WMS1.

D1 хранит карточки, снимки характеристик в заказах, назначения, версии сессий,
операции и авторов, сообщения о проблемах. IndexedDB изолирована по ID пользователя:
это кэш доступных заказов и очередь несинхронизированных изменений, не вторая
общая база. Первый вход требует связи и Cloudflare Access. API не кэшируется
service worker. Старые локальные базы не удаляются и не присваиваются новому
пользователю автоматически.

Комментарии не меняют статус сборки. Сообщения о новом месте доступны другим
сборщикам, в чьих заказах есть товар; администратор подтверждает изменение
карточки с проверкой её версии. «Нет товара» создаёт запрос проверки резерва.
Роль «Водитель погрузчика» видит очередь отсутствий: проверяет резерв, пополняет,
отмечает готовность. Наличие в верхнем резерве не выдумывается; таблица
`stock_balances` подготовлена для ручных / симулированных / WMS1 данных.

## Подготовка Cloudflare (выполняет владелец)

Сделайте резервную копию действующей D1 и экспорт старых локальных заказов/товаров.
Проверьте сохранность копий перед переключением. Миграция добавляет таблицы и
колонки; существующие товары и пользователи не удаляются.

В терминале проекта:

```powershell
New-Item -ItemType Directory -Force .backups
npx wrangler d1 export DB --remote --output .backups/warehouse-before-operations.sql
npx wrangler d1 migrations apply DB --remote
npx wrangler r2 bucket create warehouse-pilot-product-images
npm ci
npm run check
npx wrangler deploy --keep-vars
```

Если R2 bucket уже существует, повторно его создавать не надо. Binding
`PRODUCT_IMAGES` уже описан в `wrangler.jsonc`. Создание bucket может потребовать
включения R2 в аккаунте; включение/оплату подтверждает владелец.

Папка `.backups/` исключена из Git. SQL-экспорт содержит рабочие данные:
храните копию отдельно и не добавляйте её в репозиторий.

Переменные `TEAM_DOMAIN`, `POLICY_AUD`, `BOOTSTRAP_ADMIN_EMAIL` и секрет
`OPENAI_API_KEY` сохраняются. Не помещайте ключи в React или публичный git.
Опциональная runtime-переменная `AI_DAILY_REQUEST_LIMIT` ограничивает суммарное
число запросов OCR/сверки на администратора в сутки UTC (по умолчанию 20,
0 отключает). Дополнительно максимум 3 обращения в минуту. Неуспешные попытки
могут учитываться; это ограничение запросов, не денежный биллинг.

GitHub Actions теперь проверяет проект, а не публикует неработающий статический
фронт на Pages. Для Cloudflare Git Builds: build `npm run check`, deploy
`npx wrangler deploy --keep-vars`. Миграции рабочей базы применяются отдельно
до выпуска кода. Не включайте одновременно автоматический и ручной деплой
одного выпуска без необходимости.

## Проверка после выпуска

1. Войти администратором, открыть общую базу; проверить описание, фото и размеры.
2. Перенос старых карточек не перезаписывает конфликтующие поля. Ошибки фотографий
   R2 показываются отдельно; исходные локальные картинки остаются на устройстве.
3. Создать тестовый заказ по фото/JSON и назначить сборщику.
4. На телефоне сборщика открыть его, начать сборку, оставить комментарий,
   отметить отсутствие. Комментарий не должен блокировать завершение.
5. Проверить репорт администратором и очередь водителя погрузчика.
6. Отключить сеть в уже открытом приложении, изменить прогресс, вернуть связь.
   Надпись об ожидании отправки должна исчезнуть после синхронизации.
7. Изменить один заказ на двух устройствах: второе изменение не должно
   молча перезаписывать первое. При конфликте доступно подтверждаемое принятие
   серверной версии, с потерей только явно отменённых локальных отметок.
8. Войти другим пользователем в том же браузере: прежний каталог администратора
   и его заказы не должны появиться.

Палетирование — эвристическая рекомендация, не инженерная сертификация. Все
коробки учитываются либо размещением, либо явной ошибкой. Ограничения высоты и
массы настраиваются; 180 см / 800 кг — начальные параметры, не измерения вашей
тары. Проверяется передача веса вниз по опорам и видимость вертикальных граней,
но не деформация картона, трение, динамика погрузчика и реальное качество упаковки.
Демонстрационные габариты всегда отмечаются как симулированные.

Фактически установленные коробки синхронизируются через `pallet_states` с
проверкой версии и прав на заказ. Для демо-заказов используется только устройство.
Невалидная фактическая опора блокирует дальнейшее автоматическое размещение,
а не переставляется алгоритмом молча. Очередь сообщений и уведомления администратора
обновляются раз в 15 секунд (уведомления — пока приложение открыто и видно).
В заказе сборщика предупреждения обновляются раз в 30 секунд. Системные push-уведомления
при закрытом приложении и настоящий коннектор WMS1 в этот выпуск не входят.

## Обновление: итоги сборки, фото сообщений и экспорт каталога

Перед публикацией этой версии примените `0004_report_photos.sql`:

```powershell
npx wrangler d1 migrations apply DB --remote
npm run check
npx wrangler deploy --keep-vars
```

Миграция добавляет только nullable-поле `reports.photo_key`. Сначала сделайте
резервную копию D1 по инструкции выше. Новый bucket или дополнительные runtime-переменные
не нужны: фото сообщений сохраняются в существующем `PRODUCT_IMAGES` с префиксом
`reports/`. Он остаётся закрытым. Фото выдаёт только авторизованный API с проверкой
роли и доступа к товару; водитель погрузчика видит только фото к отсутствиям.

К сообщению можно приложить один снимок с камеры или из галереи. Браузер уменьшает
его до 1280 px по большей стороне и перекодирует в JPEG без EXIF. До подтверждения
сервером фото вместе с сообщением хранится в пользовательской очереди IndexedDB.
Пустой комментарий допустим при наличии фото; для другого местоположения всё равно
нужен адрес. Повторная отправка того же ID не создаёт второе сообщение или вложение.

«Скачать БД товаров» в панели администратора выгружает все страницы активного каталога
в JSON `warehouse-pilot.products`, включая встроенные фотографии, описание, адреса
и характеристики. Поиск на экране не ограничивает выгрузку. Это переносимый экспорт
каталога, а не SQL-копия заказов, пользователей или аудита. При ошибке скачивания
фото экспорт прерывается с сообщением, а не создаёт незаметно неполную копию.
Рекомендуется запускать экспорт вне редактирования каталога: это постраничное чтение,
не транзакционный снимок на одну секунду. Сборщику экспорт запрещён на сервере.

После выпуска проверьте фото с телефона, уведомление на другой вкладке администратора,
экспорт с активным поиском, итоговый экран завершённого заказа и повторное открытие
заказа после восстановления сети. Итоговая панель отличает локальное завершение от
подтверждённого сервером и показывает длительность без пауз.
